# Strike Finance Vaults

| Environment | Base URL |
|-------------|----------|
| Mainnet | `https://api.strikefinance.org` |
| Testnet | `https://api-v2-testnet.strikefinance.org` |

Signed requests use the API wallet headers from **strike-auth** (`authenticatedFetch` / `signRequest`). Leader order entry is in **strike-trading**, vault account/position/history reads in **strike-account** and **strike-history**, and the WebSocket protocol in **strike-userstream**.

## Concepts

- **A vault is its own trading account.** `account_id` is `vault_` plus the first 8 characters of `vault_id` (e.g. `vault_536b4d72`). The leader trades it by adding `vault_id` to ordinary order requests. Anyone can read its account, positions, orders and history.
- **Types.** `user`: created by any account, which becomes the leader. Default 10% Leader Fee, leader must keep 5% of shares. `protocol`: created by Strike admins (e.g. the SLP liquidity vault). Leader Fee is 0, auto-verified, no 5% rule, and only admins can pause it or change its Recovery settings. Find protocol vaults with `GET /v2/vaults?type=protocol`.
- **Share price (NAV).** `equity = wallet balance + unrealized PnL` of the vault account, and `share_price = equity / total_shares` (`1` while there are no shares). A new vault starts at price 1 with `total_shares = initial_deposit`.
- **Deposits mint shares** at the current share price: `floor(usd_amount / share_price, 8 decimals)`. Your `avg_entry_price` = `(prev_shares × prev_avg + usd_amount) / (prev_shares + minted)`, i.e. total USD paid ÷ shares held, rounded to 12 decimals. Deposits settle when the engine processes them (async). There is no lock-up on depositing.
- **Withdrawals are deferred.** A request locks shares. After `lockup_days × 24h` the engine executes it automatically at the share price at that time, not the estimate from the request time. Leader Fee is charged on profit at that point (see the lifecycle below).
- **Status.** `active`, `paused` or `closed`. Only `active` vaults accept new orders and deposits (see the pause caveat below). `closed` cannot be set through the public API.
- All amounts are decimal **strings**. Request amounts on create, deposit and withdraw must be JSON strings (`"250"`, not `250`). Timestamps are Unix ms unless noted.

## Who Can Call What

| Group | Routes |
|-------|--------|
| Public | `GET /v2/vaults`, `/v2/vault/:id`, `/v2/vault/:id/history`, `/v2/vault/:id/portfolio`, `/v2/vault/:id/depositors`, `/v2/vault/:id/liquidations`, `/v2/vault/:id/announcements` |
| FlexibleAuth (own account, or public `account_id` / `blockchain_address`) | `GET /v2/vault/position`, `/v2/vault/positions`, `/v2/vault/history`, `/v2/vault/my-deposits/history` |
| API wallet or JWT, current leader only | `GET /v2/vault/:id/recovery-settings` |
| Trading + masterOnly | `POST /v2/vault/create`, `/v2/vault/deposit`, `/v2/vault/withdraw`, `/v2/vault/:id/withdrawals/:withdrawal_id/cancel`, `/v2/vault/:id/pause`, `/v2/vault/:id/resume`, `PATCH /v2/vault/:id/recovery-settings` |
| JWT-only (Strike app) | `POST /v2/vault/:id/announcements`, `DELETE /v2/vault/:id/announcements/:announcement_id`, `POST /v2/staking-rewards/vault-deposit` |

- masterOnly routes reject API wallets bound to a sub-account with `403 {"error":"not available to sub-account API keys"}`. Writes always act on the wallet's own (master) account. There is no `sub_account_id` on vault routes.
- Every vault route can return `503 {"error":"service unavailable"}` while the API warms up.
- Create, deposit, withdraw, cancel and recovery-settings writes are **async**. `200` means the command was queued for the engine. The outcome arrives as a `VAULT_*` user-stream event (see [Async Outcomes](#async-outcomes)). The `request_id` is generated by the server; only recovery settings accept your own. Nothing is idempotent, so a blind retry deposits or withdraws twice. Pause and resume apply immediately.

## Public Reads

### GET /v2/vaults

| Query | Default | Notes |
|-------|---------|-------|
| `status` | `active` | `active` \| `paused` \| `closed`. Anything else: `400 invalid status filter, must be 'active', 'paused', or 'closed'` |
| `type` | all | `user` \| `protocol` (`400 invalid type filter, must be 'user' or 'protocol'`) |
| `leader_account_id` | | Vaults led by this account |
| `depositor_account_id` | | Vaults where this account holds shares > 0 |
| `is_verified` | | `true` \| `false` (`400 invalid is_verified filter, must be 'true' or 'false'`) |

### GET /v2/vault/:id

Returns the same object as a list item. The live fields (`share_price`, `equity`, `wallet_balance`, `all_time_*`) are filled in. The list-only metrics are not computed here: `apr`, `period_start_*` and `sharpe_ratio` are absent, `return_24h`, `period_return` and `fee_earned` are `""`, and `depositors` is `0`. Use `/portfolio` for metrics. Any failure, including an unknown id, returns `404 {"error":"vault not found"}`.

  "history": [[1792393200000, "1966.79", "-24.31", "0", "5", "0.986686308224365484"]]

```

- `total_value_locked` is the vault equity. `fee` is the Leader Fee in percent (`commission_bps / 100`). `volume` is the trading volume within the period. `max_drawdown` is the peak-to-trough share-price drop in percent over the period. `sharpe_ratio` and `max_drawdown` are omitted when there is not enough history. `sharpe_ratio` is also omitted when daily returns have zero spread. `period_start_share_price` / `period_start_timestamp` are omitted when there is no baseline snapshot.
- `pending_fees_owed` is the unrealized Leader Fee on profitable depositors at `pending_fees_share_price`. To track it live at share price `p`, compute `max(0, commission_bps/10000 × (p × pending_fees_profitable_shares − pending_fees_profitable_basis))`.
- `total_liquidation_fees_earned` is the lifetime liquidation-fee income (in practice SLP) from a snapshot refreshed every minute. It does not depend on `period`. Don't add it to TVL or PnL, because it is already part of equity.
- `vault_history` rows: `[ts_ms, tvl, pnl, fees_accrued, depositors, share_price]`. Every value after the number timestamp is a **string**, including `depositors`. `account_history` rows: `[ts_ms, cumulative_volume]`. `history` is a deprecated copy of `vault_history`.
- Chart buckets: hourly for `24h`/`7d`/`30d`, daily for `6m`/`1y`. `all` gives daily points from creation, then hourly points for the last 30 days.
- Errors: `404 vault not found`, `503 vault data is temporarily unavailable` (liquidation snapshot missing).

All deposits and withdrawals in the vault. Query: `type` (`deposit` | `withdrawal`), `status` (`completed` | `pending` | `cancelled` | `failed`), `limit` (default 100, max 500), `pagination` (the previous `next_cursor`). Results are sorted newest first.

     "account_id": "019d06a7-...", "address": "0x6139...", "status": "completed", "timestamp": 1790353503572,
     "shares_burned": "51.10033743", "estimated_usd": "50.99999999683", "actual_usd": "50.83019673199",
     "share_price": "0.998036462414611994", "execution_share_price": "0.994713524184141348",
     "leader_fee": "0", "avg_entry_price": "0.998036462519",
     "execute_at_timestamp": 1790439903572, "executed_timestamp": 1790439904255}
  ],
  "limit": 100,
  "next_cursor": "eyJzb3J0X2F0Ijoi..."

```

- Deposit rows: `usd_amount`, `shares_minted`, `share_price`. Withdrawal rows: `timestamp` is the request time, `share_price` / `estimated_usd` are from the request, `execute_at_timestamp` is when it becomes eligible. `actual_usd`, `execution_share_price` and `leader_fee` appear only on `completed` rows. `executed_timestamp` is the completion **or cancellation** time. `avg_entry_price` is the depositor's basis at request time.
- `funding_source`: `credit` (Credit-line draw or Credit-encumbered withdrawal), `staking_reward`, or absent for the main balance. Credit withdrawals add `credit_user_usd` / `credit_facility_usd` (both `"0"` while pending).

- Status values: deposits are always `completed`. Withdrawals are `pending` → `completed` or `cancelled`. `failed` is accepted as a filter, but no current flow writes it.

### GET /v2/vault/:id/depositors

Query `limit` (default 100, max 500) and `pagination`. Sorted by shares (desc), then account id (desc). Positions worth less than $1 at the current share price are hidden. `count` is the total number of visible depositors.

```json
{
  "depositors": [{
    "address": "addr1q80f...", "nickname": "MARKET WIZARDS", "avatar_url": "...",
    "deposited": "1576.917904789866192", "total_deposited": "2083.9", "total_withdrawn": "506.982095210133808",
    "current_equity": "1506.453927798936849", "share_percentage": "79.14728892381099448",
    "pnl": "-70.463976990929343", "deposited_since": 1789833609281
  }],
  "count": 5, "limit": 100, "next_cursor": null
}
```

`address` is the depositor's wallet address, or the account id when there is none. `deposited` = `total_deposited − total_withdrawn`. `pnl` = `current_equity + total_withdrawn − total_deposited`. Errors: `400 invalid limit parameter`, `400 invalid pagination cursor`, `404 vault not found`, `503 vault data is temporarily unavailable`.

### GET /v2/vault/:id/liquidations

Liquidation-fee income credited to the vault account. This is the SLP Liquidations tab. Other vaults return `[]`. Query: `limit` (positive, default 50, max 100), `symbol`, `startTime` / `endTime` (inclusive ms, `0` = unbounded), `pagination`. Sorted by `timestamp` desc, then `id` desc. A cursor is only valid with the same vault and filters.

```json
{
  "vault_id": "3fd3ab0b-...",
  "liquidations": [{
    "id": 7537666, "timestamp": 1792418453885, "symbol": "ADA-USD", "fill_id": 4346759, "order_id": 11076081340,
    "side": "sell", "position_side": "long", "price": "0.21675", "size": "785", "notional": "170.14875",
    "liquidation_fee_earned": "0.45063983"
  }],
  "limit": 50, "next_cursor": null
}
```

Each row is one fee receipt. `side` is the side of the liquidating execution and `position_side` is the side of the closed position. `order_id`, `side`, `position_side`, `price`, `size` and `notional` are `null` when the fill is missing or archived. `fill_id` is `null` only on legacy order-level receipts. Errors: `400 invalid limit parameter`, `400 invalid startTime parameter` / `invalid endTime parameter`, `400 invalid vault liquidations query` (symbol over 100 chars, or `startTime > endTime`), `400 invalid vault pagination cursor`, `404 vault not found`.

### The vault's trading account

The vault's trading account can be read publicly with `vault_id=<vault UUID>` on `GET /v2/account`, `/v2/balances`, `/v2/portfolio` (**strike-account**), `/v2/positions`, `/v2/closedPositions`, `/v2/history/order|fill|position|funding|transaction` (**strike-history**), and `/v2/openOrders`, `GET /v2/order`, `/v2/algo/twap` (**strike-trading**). ## Depositor Reads (FlexibleAuth)

The depositor is resolved in this order: `account_id` (UUID), then `blockchain` + `blockchain_address`, then `blockchain_address`, then the authenticated caller. Here `vault_id` only selects the vault and never identifies the depositor, so `GET /v2/vault/position?vault_id=X` with no identity and no auth returns `401 {"error":"authentication required or provide vault_id, account_id, or blockchain_address"}`. Other errors: `400 invalid account_id`, `400 blockchain_address is too long` (> 512), `400 invalid address format`, `404 user not found`, `503 vault data is temporarily unavailable`.

### GET /v2/vault/position

`vault_id` is required (`400 vault_id is required`). Unknown vault: `404 vault not found`.

```json
{
  "vault_id": "536b4d72-...", "name": "MARKET WIZARDS",
  "shares": "1577.67038477", "shares_locked": "0", "available_shares": "1577.67038477",
  "total_deposited": "2083.9", "total_withdrawn": "506.982095210133808",
  "avg_entry_price": "0.999974402277", "current_value": "1516.699344488656549",
  "net_contribution": "1576.917904789866192", "unrealized_pnl": "-60.93065551184880544",
  "total_pnl": "-60.218560301209643"
}
```

- `shares_locked` = shares in pending withdrawals. `available_shares = shares − shares_locked`.
- `current_value = shares × share_price` and `unrealized_pnl = shares × (share_price − avg_entry_price)`.
- `total_pnl = current_value + total_withdrawn − total_deposited` and `net_contribution = total_deposited − total_withdrawn`.
- With no current position, `shares`, `shares_locked`, `available_shares`, `current_value` and `unrealized_pnl` are `"0"`. `total_deposited`, `total_withdrawn` and `net_contribution` keep their lifetime values, `total_pnl = total_withdrawn − total_deposited`, and `avg_entry_price` is the last basis, or the current share price if the account never held shares.

### GET /v2/vault/positions

`{"positions": [ /* same object, one per vault with shares > 0 */ ]}`. The value is `null` (not `[]`) when the account holds no vault shares.

### GET /v2/vault/history

The depositor's own deposits and withdrawals across vaults. Query: optional `vault_id` (must be a UUID, otherwise `500 failed to retrieve vault history`), `type`, `status`, `limit`, `pagination`, same as the public history. Rows have the same shape without `account_id` / `address`. The response adds `"count"`, the number of rows on this page.

### GET /v2/vault/my-deposits/history

Depositor equity curve: `{"history": [[ts_ms, "equity", "pnl"], ...]}`. Equity = Σ shares × share price over the depositor's vaults, and pnl = equity − net deposits. Optional `vault_id` limits it to one vault. Points are hourly for the last 30 days, plus daily points before that for accounts older than 30 days.

## Depositor Writes

### POST /v2/vault/deposit

```json
{ "vault_id": "536b4d72-687d-5e8e-a3be-cef0757c795f", "usd_amount": "250" }
```

Response: `{"success": true, "request_id": "uuid", "message": "deposit request submitted"}`.

The deposit is debited from the account's **withdrawable** balance (free margin). The engine then checks, and failures arrive as `VAULT_DEPOSIT_FAILED`:
- the vault exists and is `active`
- `usd_amount ≥ min_deposit`
- there is enough withdrawable balance
- at least `0.00000001` share would be minted

Sync errors: `400 invalid request` (missing field or non-string value), `400 invalid usd_amount`, `400 usd_amount must be positive`, `500 failed to process deposit`. The API does not check that the vault exists, so an unknown `vault_id` also returns `200`, followed by `VAULT_DEPOSIT_FAILED`.

### POST /v2/vault/withdraw

```json
{ "vault_id": "536b4d72-...", "shares": "100.5" }
{ "vault_id": "536b4d72-...", "withdraw_all": true }
```

| Field | Type | Notes |
|-------|------|-------|
| `vault_id` | string | Required |
| `shares` | string | Required unless `withdraw_all`. Positive, **at most 8 decimals**. Drawn from available unencumbered shares |
| `withdraw_all` | bool | Withdraws every available share, including Credit-encumbered ones. `shares` is ignored |
| `unencumbered_shares`, `credit_line_sources[{collateral_asset, shares}]`, `confirm_debt_remainder` | | Credit-line holders only: an explicit split between free and Credit-encumbered shares. The total must equal `shares`. Not allowed with `withdraw_all` |

The body is decoded strictly: unknown fields, a second JSON object, non-string amounts or an empty `vault_id` all return `400 {"error":"invalid request"}`.

Response: `{"success": true, "request_id": "uuid", "message": "withdrawal request submitted"}`. **`request_id` is the `withdrawal_id`.**

Sync errors (400): `shares is required unless withdraw_all is true`, `invalid shares`, `shares must be positive`, `partial withdrawal shares must have at most eight decimals; use withdraw_all for an exact full balance`, `withdraw_all cannot include explicit source fields`, `explicit source shares must equal shares`, plus `invalid unencumbered_shares` / `invalid credit_line_sources` / `duplicate credit_line_sources collateral_asset` variants. `500 failed to process withdrawal`.

Engine checks, reported as `VAULT_WITHDRAWAL_REQUEST_FAILED`:
- you hold a position and enough available shares
- the share price is positive
- the 5% leader rule (see below)

Withdrawal requests are accepted while the vault is `paused`.

### POST /v2/vault/:id/withdrawals/:withdrawal_id/cancel

No body. Response: `{"success": true, "message": "withdrawal cancelled successfully"}`. The shares unlock when the engine applies it (`VAULT_WITHDRAWAL_CANCELLED`). Works any time until the withdrawal executes.

Errors: `404 withdrawal not found` (unknown, already executed or already cancelled), `403 unauthorized to cancel this withdrawal` (not yours), `404 vault_id does not match withdrawal`, `500 failed to cancel withdrawal`.

### Withdrawal lifecycle

```
POST /v2/vault/withdraw ──▶ VAULT_WITHDRAWAL_REQUESTED  (shares locked, history row "pending")
        │                    execute_at_timestamp = request time + lockup_days × 24h
        ├── cancel ──▶ VAULT_WITHDRAWAL_CANCELLED       (shares unlocked, row "cancelled")
        ▼ (automatic, at or after execute_at_timestamp)
   liquidity check ── short ──▶ cancel vault orders (farthest from mark first)
        │                       ──▶ RFQ per planned order group (requester = vault, leader excluded)
        │                       ──▶ ~1 s later: reduce-only IOC limit orders, client_order_id "vault_wd_<order_id>",
        │                           price bound min(5%, market order_limit_price_bound) from mark
        │                       ──▶ retry every 10 s until cash and capacity suffice
        ▼
   VAULT_WITHDRAWAL_EXECUTED  (shares burned, USD credited to your balance, row "completed")
```

- **Payout**: `gross = shares × share_price` at execution, after any unwind. Your proceeds absorb the unwind slippage.
- **Leader Fee**: `commission_bps/10000 × max(0, exec_share_price − avg_entry_price_at_request) × shares`, capped at `gross`, so `net = gross − fee`. There is no fee on the leader's own withdrawals or in protocol vaults. The fee stays in the vault as **new shares minted to the leader** at the execution price (`VAULT_LEADER_FEE_EARNED`).
- **Unwind style**: with `allow_proportional_close: true`, each position is reduced in proportion to the withdrawn share fraction. Otherwise each round closes 10% of the single largest position by notional at mark, for up to 10 rounds per attempt, stopping once cash and capacity suffice. The leader's bots see these orders with `act`/`auto_close_type` `vault_withdrawal`, and canceled orders with close reason `vault_withdrawal`.
- Only one withdrawal per vault holds execution capacity at a time. Others stay `pending` until it finishes.
- Capacity is limited by the vault's Recovery max margin ratio (below). A payout may not push the vault's cross margin ratio above it.
- On retryable failures `VAULT_WITHDRAWAL_EXECUTE_FAILED` is emitted, deduplicated by error text, with `request_id` = `withdrawal_id`. A non-retryable failure marks the withdrawal blocked, emits one `VAULT_WITHDRAWAL_EXECUTE_FAILED` and stops automatic retries. Either way it stays `pending` and can still be cancelled. RFQ details are in **strike-rfq**.

## Leader Operations

### POST /v2/vault/create

```json
{
  "name": "Momentum Vault",
  "description": "BTC/ETH trend following",
  "initial_deposit": "1000",
  "leader_commission_bps": 1000,
  "lockup_days": 1,
  "min_deposit": "100",
  "allow_proportional_close": false
}
```

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `name` | string | yes | Non-empty. The database column is 255 chars |
| `description` | string | no | |
| `initial_deposit` | string | yes | ≥ `100` (API) and ≥ `min_deposit` (engine). Taken from your withdrawable balance |
| `leader_commission_bps` | integer | no | 0–5000, default 1000 (10%). **`0` is replaced with 1000 by the engine**, so the lowest effective fee is 1 bps |
| `lockup_days` | integer | no | 1–30, default 1 |
| `min_deposit` | string | no | > 0, default `100` |
| `allow_proportional_close` | bool | no | Default `false` (iterative 10% unwind) |

`min_leader_share_pct` is always 5. There is no creation fee. The leader starts with `initial_deposit` shares at price 1.

**5% rule (user vaults):** a withdrawal request by the leader is rejected if the leader's remaining shares would fall below 5% of current `total_shares` (`leader must maintain at least 5% of vault shares: minimum=…, would_have=…`). Each request is checked on its own: "remaining" means the leader's total shares, including shares already locked by earlier pending requests, minus this request. Deposits by others can still dilute the leader below 5%.

Response: `{"success": true, "request_id": "uuid", "message": "vault creation request submitted"}`. The new `vault_id` is not returned. Find it with `GET /v2/vaults?leader_account_id=<your account_id>`.

Errors:
- `400 invalid request: <binding error>` (missing `name` / `initial_deposit`, wrong JSON types)
- `400 invalid initial_deposit`, `400 initial_deposit must be at least 100 USD`
- `400 invalid min_deposit`, `400 min_deposit must be positive`
- `400 leader_commission_bps must be between 0 and 5000`, `400 lockup_days must be between 1 and 30`
- `409 user can only create one vault at a time` (you already lead an `active` vault)
- `500 failed to process vault creation`

Engine rejections arrive as `VAULT_CREATE_FAILED`, e.g. `initial deposit must be at least <min_deposit> USD` or `insufficient_balance`.

### POST /v2/vault/:id/pause · POST /v2/vault/:id/resume

No body. Response: `{"success": true, "vault_id": "...", "new_status": "paused", "message": "vault paused"}` (resume: `"active"` / `"vault active"`).

- Errors: `404 vault not found`, `403 protocol vaults can only be managed by admins`, `403 only vault leader can manage this vault`, `500 failed to update vault`.
- While `paused`: `POST /v2/order`, the replace endpoints and `/v2/order/strategy` with this `vault_id` return `403` (see **strike-trading**). `/v2/orders/batch` returns `200` with each item in `failed: [{index, error: "vault trading is paused"}]`. Cancels, leverage/margin changes, TWAP creation, grid-bot creation, withdrawal requests and withdrawal execution keep working.
- Pause and resume are applied by the API, not sequenced through the matching engine. Deposit rejection happens in the engine and may not take effect immediately, and a later engine update to the vault (a deposit or a withdrawal settlement) can set the status back to `active`. Re-read `GET /v2/vault/:id` before relying on it.

### GET · PATCH /v2/vault/:id/recovery-settings

Recovery max margin ratio: the highest cross margin ratio (maintenance margin ÷ margin balance) the vault may be left at when Strike pays out of it, for ordinary withdrawals and Credit recovery. A lower value means less cash can be paid out before positions are unwound. Range `(0, 0.5]`. `0` means the protocol default `0.5`. Only the current leader of a **user** vault can read or change it.

```json
// GET
{ "vault_id": "...", "configured_vault_recovery_max_margin_ratio": "0",
  "effective_vault_recovery_max_margin_ratio": "0.5",
  "pending": { "vault_recovery_max_margin_ratio": "0.3", "seq": 70804210, "request_id": "...",
               "provenance": { "actor_account_id": "019fb258-...", "admin_name": null } } }
```

`pending` is `null` when no change is waiting.

PATCH body: `{"vault_recovery_max_margin_ratio": "0.3", "request_id": "optional-client-id"}`. The ratio is required and may be a string or a number. The body is decoded strictly. Response:

```json
{ "success": true, "request_id": "...", "sequence_id": 70804210, "message_id": "1775914565478-1",
  "submitted_vault_recovery_max_margin_ratio": "0.3", "effective_vault_recovery_max_margin_ratio": "0.5" }
```

The engine stores the value as `pending`, and it takes effect during a later Credit collateral-price evaluation. The leader's stream then receives `VAULT_RECOVERY_SETTINGS_PENDING` / `VAULT_RECOVERY_SETTINGS_ACTIVATED` (`vault_id`, `current_effective_ratio`/`pending_ratio`, `previous_effective_ratio`/`new_effective_ratio`). Engine rejections produce no event, so confirm with GET.

Errors: `401 missing authorization header` (no auth), `400 invalid request` (unknown field or missing ratio), `400 vault Recovery max margin ratio must be zero or in (0,0.50]`, `403 vault recovery settings require the current Vault Leader` (also returned for protocol vaults), `404 vault not found`, `500 failed to load Vault Recovery settings`, `500 failed to publish command`.

### Trading the vault

Add `"vault_id": "<vault UUID>"` to `POST /v2/order`, `/v2/orders/batch`, the replace endpoints, `/v2/order/strategy`, `DELETE /v2/order/cancel|cancel-all`, `/v2/leverage`, `/v2/marginMode`, `PUT /v2/symbols`, `/v2/isoMargin`, `POST /v2/algo/twap`, `POST /v2/grid/bot` and `DELETE /v2/grid/bot/:id` (**strike-grid-bot**), and RFQ create (**strike-rfq**). `DELETE /v2/algo/twap/:id` and read endpoints take it as a query parameter. Full rules are in **strike-trading**:

- Only the leader can trade: `403 only vault leader can trade on vault account` (create) or `403 only vault leader can perform this action on vault account` (other routes).
- New orders need an `active` vault: `403 vault trading is paused` (create) or `403 vault is paused` (replace/strategy). Batch items fail individually in `failed[]`. Cancels work in any status.
- Unknown vault: `404 vault not found`. `vault_id` and `sub_account_id` are mutually exclusive (`400`).
- Builder-fee approval is checked on the leader's account, not the vault.

## Async Outcomes

Vault events arrive as wrapped `ACCOUNT_UPDATE`s: `{"e":"ACCOUNT_UPDATE","E":…,"data":{"event_type":"VAULT_…","event_data":{…}}}`. See **strike-userstream** for logon and subscription. Each event goes to the stream of the account in `event_data.account_id`. Decimals in `event_data` are strings, timestamps are numbers in ms, and empty fields are omitted.

| `event_type` | Delivered to | `event_data` |
|--------------|--------------|--------------|
| `VAULT_DEPOSITED` | Depositor | `request_id`, `vault_id`, `vault_name`, `usd_amount`, `share_price`, `shares` (minted), `timestamp`, `account_id`, `funding_source`?, `liquidation_reset`? |
| `VAULT_WITHDRAWAL_REQUESTED` | Depositor | `withdrawal_id`, `vault_id`, `vault_name`, `account_id`, `shares`, `estimated_usd`, `share_price`, `request_timestamp`, `execute_at_timestamp`, `avg_entry_price` |
| `VAULT_WITHDRAWAL_EXECUTED` | Depositor | `withdrawal_id`, `vault_id`, `shares_burned`, `share_price`, `gross_usd`, `leader_fee`, `leader_shares_minted`, `leader_account_id`, `net_usd`, `actual_usd`, `execution_share_price`, `remaining_shares`, `execution_timestamp`, `account_id`, `credit_user_usd`, `credit_facility_usd` |
| `VAULT_WITHDRAWAL_CANCELLED` | Depositor | `withdrawal_id`, `vault_id`, `shares_unlocked`, `account_id` |
| `VAULT_LEADER_FEE_EARNED` | Leader | `vault_id`, `withdrawal_id`, `shares_minted`, `fee_usd`, `share_price`, `new_leader_shares`, `new_leader_avg_entry`, `execution_timestamp`, `account_id` |
| `VAULT_CREATE_FAILED`, `VAULT_DEPOSIT_FAILED`, `VAULT_WITHDRAWAL_REQUEST_FAILED`, `VAULT_WITHDRAWAL_CANCEL_FAILED`, `VAULT_WITHDRAWAL_EXECUTE_FAILED` | Caller (leader for create) | `account_id`, `request_id`, `error`, `timestamp`. `request_id` matches the create/deposit/withdraw response. For execute failures it is the `withdrawal_id`. For cancel failures it is an internal id the API never returned |
| `VAULT_CREATED` | **Vault** stream (`account_id` = `vault_…`) | `request_id`, `vault_id`, `account_id`, `vault_type`, `name`, `description`, `leader_account_id`, `leader_commission_bps`, `initial_deposit`, `total_shares`, `min_leader_share_pct`, `lockup_days`, `min_deposit`, `allow_proportional_close`, `is_verified`, `timestamp` |
| `VAULT_LIQUIDATION_INCOME` | Vault stream | `account_id`, `liquidation` (same object as a `/liquidations` row) |
| `VAULT_RECOVERY_SETTINGS_PENDING` / `_ACTIVATED` | Leader | See Recovery settings |

Balance updates (`data.e` = `ACCOUNT_UPDATE`) carry these `r` reasons:
- Your account: `VAULT_CREATE`, `VAULT_DEPOSIT`, `VAULT_DEPOSIT_FROM_STAKING`, `VAULT_WITHDRAWAL`.
- The vault account: `VAULT_CREATE_RECEIVED`, `VAULT_DEPOSIT_RECEIVED`, `VAULT_WITHDRAWAL_EXECUTED`.

Common engine `error` texts:
- `vault not found: <id>`, `vault is not active: status=paused`
- `deposit amount must be at least <min_deposit> USD` (the vault's own `min_deposit`), `insufficient_balance`, `deposit amount is below Vault Share precision`
- `user already has an active vault: <id>`
- `no position found for account <a> in vault <v>`, `insufficient available shares: have=…, need=…`
- `leader must maintain at least 5% of vault shares: minimum=…, would_have=…`
- `pending withdrawal not found: <id>`, `no locked shares found for account <a> in vault <v>`
- Retry reasons such as `retryable vault withdrawal: withdrawal is still locked until <ms>` or `…insufficient protected Vault capacity after cascade: have=…, need=…, shortfall=…`

**Watching a vault**: subscribe with `{"method":"subscribe","channel":"userstream","vault_id":"<vault UUID>","id":1}`. No logon is needed. You receive the vault account's `ORDER_TRADE_UPDATE`s (the leader's trades), position and balance updates, and `VAULT_LIQUIDATION_INCOME`. `VAULT_CREATED` fires only once, at creation, normally before anyone can subscribe. Depositor events go only to each depositor's own authenticated stream.

## Gotchas

- **Amounts are JSON strings** on create, deposit and withdraw (`"250"`), and integers for `leader_commission_bps` / `lockup_days`. A JSON number in a string field returns `400`.
- **Shares have 8 decimals.** Truncate before you send a partial `shares`. Use `withdraw_all: true` to leave no dust.
- **Estimated ≠ actual**: `estimated_usd` uses the request-time price. The payout uses the execution-time price, minus Leader Fee and unwind slippage.
- **Liquidation reset**: if a vault's share price reaches `0`, the next deposit resets it. Existing shares are wiped, pending withdrawals are cancelled, and the depositor gets shares at price 1 (`liquidation_reset: true`).
- The vault `account_id` (`vault_…`) works for user-stream subscriptions but **not** as an `account_id` query parameter on REST. Use `vault_id` there.
- **Two invalid-`period` behaviors**: `GET /v2/vaults` returns `500`, and `/portfolio` returns `404 vault not found`.
- `period_start_timestamp` is in **seconds**. Every other timestamp is in ms.
- `GET /v2/vault/:id` does not compute `apr`, returns, `depositors` or `fee_earned`. Use `/portfolio` or the list.
- Public `/history` and `/depositors` expose depositor wallet addresses and profiles.

## TypeScript Example

```typescript
import { authenticatedFetch } from "./auth"; // strike-auth helper

const BASE = "https://api.strikefinance.org";
const PRIVATE_KEY: Uint8Array = loadApiWalletPrivateKey();
const PUBLIC_KEY_HEX: string = loadApiWalletPublicKeyHex();

async function api<T>(method: string, path: string, body?: unknown): Promise<T> {
  const res = await authenticatedFetch(BASE, path, { method, body }, PRIVATE_KEY, PUBLIC_KEY_HEX);
  const json = await res.json();
  if (!res.ok) throw new Error(`${res.status} ${json.error}`);
  return json as T;
}

/** Truncate a positive decimal string to 8 places (shares must have ≤ 8 decimals). */
const toShares8 = (s: string) => { const [i, f = ""] = s.split("."); return f ? `${i}.${f.slice(0, 8)}` : i; };

// 1. Discover vaults (public, no auth)
const { vaults } = await (await fetch(`${BASE}/v2/vaults?type=user&period=30d&limit=50`)).json();
const vault = vaults.sort((a: any, b: any) => Number(b.apr) - Number(a.apr))[0];

// 2. Deposit (async: wait for VAULT_DEPOSITED / VAULT_DEPOSIT_FAILED with this request_id)
const dep = await api<{ request_id: string }>("POST", "/v2/vault/deposit",
  { vault_id: vault.vault_id, usd_amount: "250" });

// 3. Read the position (own account via API wallet)
const pos = await api<any>("GET", `/v2/vault/position?vault_id=${vault.vault_id}`);
console.log(pos.shares, pos.current_value, pos.total_pnl);

// 4. Request a partial withdrawal; request_id is the withdrawal_id
const half = toShares8((Number(pos.available_shares) / 2).toFixed(10)); // Number is exact enough below ~1e7 shares
const wd = await api<{ request_id: string }>("POST", "/v2/vault/withdraw",
  { vault_id: vault.vault_id, shares: half });

// 5. Track it; execute_at_timestamp shows once the engine has recorded the request
const { history } = await api<any>("GET",
  `/v2/vault/history?vault_id=${vault.vault_id}&type=withdrawal&status=pending`);
const pending = history.find((h: any) => h.id === wd.request_id);
console.log("executes at", pending?.execute_at_timestamp);

// 6. Changed your mind? Cancel (no body)
await api("POST", `/v2/vault/${vault.vault_id}/withdrawals/${wd.request_id}/cancel`);

// Leader: create, find the vault id, trade it, pause it
await api("POST", "/v2/vault/create", { name: "Momentum Vault", initial_deposit: "1000", lockup_days: 2 });
const me = await api<any>("GET", "/v2/account");
const mine = await (await fetch(`${BASE}/v2/vaults?leader_account_id=${me.account_id}`)).json();
const myVaultId: string = mine.vaults[0]?.vault_id; // appears once the engine processed the create
await api("POST", "/v2/order", { vault_id: myVaultId, symbol: "BTC-USD", side: "buy", type: "limit", size: "0.01", price: "60000" });
await api("POST", `/v2/vault/${myVaultId}/pause`);
```
